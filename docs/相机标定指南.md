# 相机内参标定指南（海康 MV-CU013-A0UC）

> 目标：算出这台相机的内参/畸变系数，写进 `src/ros2_hik_camera/config/camera_info.yaml`，
> 让节点发布的 `/camera_info` 是真实的（现在那份是旧的占位数据：720×540，相机实际 1280×872）。

## 0. 标定板规格

本项目配套的板子：**15 列 × 10 行的黑白格子，格长 20mm**
→ OpenCV 说的**内角点**是 **14 列 × 9 行**（格子数比内角点数各多 1）

```
--cols 14 --rows 9 --square 20      # 这三个参数就是本板子的参数
```

板子必须是**平整**的：打印后贴在硬质平板/亚克力上。格子四角翘起来会让角点位置偏，
标出来的内参会失真（表现为 RMS 偏大、重投影时直线还是弯的）。

## 1. 为什么不用 ROS 自带的 cameracalibrator

板上装了 `ros-humble-camera-calibration`，但**跑不起来**：

```
cv_bridge/__init__.py ... AttributeError: _ARRAY_API not found
```

`cv_bridge` 是按 NumPy 1.x 编译的，板上 numpy 是 2.2.6，ABI 不兼容。
为这个把 numpy 降级会连累其他包，不值得。所以用 `tools/calibrate_camera.py`——
它自己用 numpy 解图像（不碰 cv_bridge），并直接写源码目录的 camera_info.yaml。

## 2. 标定步骤

### 2.1 停掉视觉栈（只要相机，别让模型抢 CPU）

```bash
sudo systemctl stop rm.service
```

> ⚠️ 停服务会执行 `rm_clean_up.sh`，里面 `pkill -f ros` 会杀掉**命令行里含 "ros" 的进程**。
> 所以 `systemctl stop` 要**单独一行执行**，不要和 `source /opt/ros/...` 拼在同一条命令里，
> 否则会把自己的 shell 一起杀掉。

### 2.2 只起相机节点

```bash
cd /root/dart_ws_on
source /opt/ros/humble/setup.bash
ros2 launch hik_camera hik_camera.launch.py
```

确认日志里是实际分辨率（应显示 `Image format: 1280x872 bgr8`）：

```bash
ros2 topic echo /image_raw --field height --once   # 应为 872
ros2 topic echo /image_raw --field width  --once   # 应为 1280
```

### 2.3 降低曝光，防止白格过曝

棋盘格白格过曝（像素顶到 255）会把黑白边界糊掉，角点检测直接失败。

```bash
ros2 param set /hik_camera exposure_time 20000   # 20ms，比常用的 50000 暗
ros2 param set /hik_camera gain 4.0
```

标定完再调回比赛用的值（`exposure_time 50000` / `gain 8.0`）。

### 2.4 跑标定脚本

**有显示器（能弹窗口，最方便）**：

```bash
cd /root/dart_ws_on
source /opt/ros/humble/setup.bash
python3 tools/calibrate_camera.py
```

窗口按键：

| 键 | 作用 |
|---|---|
| `s` | 存一张（角点检测失败会拒收） |
| `a` | 自动连拍（默认 1s 一张），存满自动停 |
| `c` | 立刻开始标定 |
| `d` | 开关预览 |
| `q` | 退出（样本够会自动标定） |

窗口里会显示 `corner=OK/NO`：只有 `OK` 才存得进去。还会显示过曝百分比。

**ssh / 没有显示器**：

```bash
python3 tools/calibrate_camera.py --interval 1.2        # 每 1.2s 自动存一张
python3 tools/calibrate_camera.py --interval 1.5 --min-samples 30
```

存够 `--min-samples`（默认 15）会自动标定；中途退出也会用已存的图标定。

### 2.5 取景要领（决定标定质量）

一个物体 = 一组内参解，所以**姿态要多样**，不能 30 张都是同一个姿势：

- **覆盖整个画面**：中心、四个角、四条边都要出现棋盘格
- **角度多样**：正对、左右转 ±30°、前后仰 ±30°、斜置
- **距离多样**：占画面 1/3 到 2/3 都要有
- **每次只动一点**，动作太快的帧会被当成重复帧跳过
- 建议 25~35 张。少于 15 张容易标歪

## 3. 看结果

脚本会打印：

```
[针孔] 使用 28 张, 图像 1280x872
[针孔] 重投影 RMS = 0.31 px  平均 = 0.28 px  最差 = 0.55 px
[针孔] fx=1203.45 fy=1201.02 cx=639.10 cy=435.62
[针孔] 畸变 = [-0.0281 0.0093 0.0002 -0.0001 0.0]
```

RMS（重投影误差）怎么判断：

| RMS | 含义 |
|---|---|
| < 0.5 px | 很好，可以直接用 |
| 0.5 ~ 1.0 px | 可用 |
| > 1.0 px | 一般还能用，但先查是不是板子不平/样本姿态太单一 |
| > 1.5 px | 建议重拍：板子贴平、增加角度变化、检查过曝 |

**"最差"那张要单独看**：如果某张明显比其他大很多，说明那张的姿态不好（可能板子斜得太狠或只露出部分）。

## 4. 结果写去哪了

- 写入 `src/ros2_hik_camera/config/camera_info.yaml`（原文件自动备份成 `camera_info.yaml.bak`）
- 采样图片在 `calib_<时间戳>/` 目录，方便复查
- 参数化结果同时存一份 `calib_<时间戳>/calib_result.json`

**让它生效**：节点读的是 install 目录里的那份，所以标定完要同步 + 重启：

```bash
cp src/ros2_hik_camera/config/camera_info.yaml \
   install/hik_camera/share/hik_camera/config/camera_info.yaml
# 或者直接重新编译（colcon build）也会同步
sudo systemctl start rm.service
```

验证：

```bash
ros2 topic echo /camera_info --once | head -12
# image_width 应该是 1280，image_height 872（不再是旧的 720/540）
```

## 5. 镜头是鱼眼吗

不确定的话可以两种模型都算一遍对比：

```bash
python3 tools/calibrate_camera.py --fisheye
```

会分别输出针孔和鱼眼的 RMS，选 RMS 更小的那个。
鱼眼模型对应 `distortion_model: equidistant`（4 个畸变系数），针孔是 `plumb_bob`（5 个）。

## 6. 标定对瞄准有什么用

现在的瞄准误差是**经验标定**的（`params.yaml` 里的 `offset_*` 表 + `p_err` 系数），
不依赖内参。所以：

- 内参主要作用是**图像校正 / 几何计算**（比如以后要做透视变换、算真实角度、 undistort）
- 有了内参，`offset` 表的标定可以更准（畸变会让同样的像素误差在不同位置对应不同角度）
- 注意有效瞄准区域只是中心 **960×720**（见 `model_detector.cpp` 里 preprocess 的注释），
  标定和偏移标定都以这块区域为准

## 7. 收尾

```bash
sudo systemctl stop rm.service            # 停掉临时的相机节点
ros2 param set /hik_camera exposure_time 50000   # 如果相机节点还活着
ros2 param set /hik_camera gain 8.0
sudo systemctl start rm.service           # 恢复正常运行（看门狗会带起整栈）
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 角点一直检测不到 | 曝光过高 / 板子没完整入画 / 板子反光 | 降曝光增益、确认 14×9 内角点全部可见、侧着光避免反光 |
| 部分角度能检测到 | 板子只露一部分 | 整块板子都要在画面内 |
| RMS 很大（>1.5px） | 板子不平、样本姿态太单一、格子边缘磨损 | 贴平板、换角度、换新板子 |
| 提示过曝 30%+ | 白格顶到 255 | `ros2 param set /hik_camera exposure_time 10000` 再来 |
| 存不进图 | 和上一张太像（重复帧被跳） | 换个位置或角度再按 s |
| `cameracalibrator` 报 `_ARRAY_API not found` | numpy 2 与 cv_bridge ABI 不兼容 | 用本项目的脚本，别用 ROS 自带的 |
