## 二、模型接口规格（务必逐条遵守）

### 输入

| 项 | 值 |
|---|---|
| 输入名 | `images` |
| 运行格式 | **`nv12`**（YUV420SP），layout `NCHW` |
| 形状 | `1 × 3 × 576 × 768`（H=576, W=768）|
| 训练域 | RGB，`data_scale`，scale = 1/255 |
| 预处理 | **Letterbox**（等比缩放 + pad=114），BGR→RGB |

> ⚠️ **输入是 NV12，不是 RGB**。板端直接把相机 YUV/NV12 数据喂给 BPU 即可，不要再转 RGB；
> 模型内部会完成 NV12→YUV444 等处理。用 PC 验证时需自行构造 NV12 或直接用 ONNX 跑 RGB。

### 输出

`[1, 9072, 28]`，类型 **FLOAT**。`9072` 是多尺度 anchor 总数（72×96 + 36×48 + 18×24，对应 stride 8/16/32）。
每个 anchor 的 **28 维布局**（**已用计算图 `Concat_5` 的拼接顺序核实**）：

| 下标 | 长度 | 含义 |
|---|---|---|
| `[0:4]` | 4 | **box**（已解码的角点/框，坐标在 letterbox 域）|
| `[4:16]` | 12 | **12 类分数**（Sigmoid 之后，是概率 0~1）|
| `[16:20]` | 4 | **4 颜色分数**（Sigmoid 之后，是概率 0~1）|
| `[20:28]` | 8 | **4 个关键点** (k1x,k1y,k2x,k2y,k3x,k3y,k4x,k4y)，letterbox 域 |

- 置信度 `conf = max(cls_scores)`，类别 `cls_id = argmax(cls_scores)`。
- 颜色 `color_id = argmax(color_scores)`，映射为 `B/R/G/P`。

### 类别名（12 类）

```
NAMES = ["s0_o0","s0_o2","s0_o3","s0_o4","s0_o5","s0_o6",
         "s1_o0","s1_o1","s1_o3","s1_o4","s1_o5","s1_o7"]
```
（`s0`=小装甲板, `s1`=大装甲板；`oX` 为目标序号）

## 三、后处理实现要求

写一个函数，输入原始输出（`(1,9072,28)` ndarray）与 letterbox 参数，输出检测列表：

```
1. split：box = out[0,:,0:4]; cls = out[0,:,4:16]; color = out[0,:,16:20]; kpts = out[0,:,20:28]
2. conf = cls.max(1); cls_id = cls.argmax(1)
3. 阈值过滤：conf >= conf_thres（建议先取 0.25 起调）
4. 取前 top_k（如 300）候选做 NMS
5. NMS：⚠️ 按「4 关键点组成的四边形」而不是普通矩形框（见注意事项 6）
6. 坐标反映射回原图：对 box 与 4 个关键点都做
   x = (x_letterbox - pad_x) / scale ;  y = (y_letterbox - pad_y) / scale
7. 关键点顺序：模型输出的 4 角点顺序与下游期望可能不同，
   参考实现里用了 KPT_ORDER = [0,3,2,1] 重排，需按实际可视化确认
8. 输出每个检测：box(xyxy)、conf、cls_id、color_id、kpts(4x2)
```

  - 第 78~138 行：**这用的是完整模型（输出已是 18 维，[box(4),conf(1),cls(1),color(4),kpts(8)]）**，
    它展示的是「后处理之后」的解析方式和坐标反映射——**是你要产出的最终结果样子**。

## 四、板端部署（RDK X5）要求

1. 把 `praysky_coord_576x768.bin` 拷到板子。
2. 用 RDK X5 官方推理接口加载（Python 用 `hobot_dnn` / `bpu_infer_lib`，C++ 用 `libdnn`；
   以官方 `rdk_model_zoo` 里的示例为准，别自己瞎找 API）。
3. 输入按 **NV12 576×768** 喂（相机若已是 YUV/NV12 可直接用；注意宽高 stride 对齐）。
4. 拿到 FLOAT 输出 `[1,9072,28]` 后，调用你的后处理，得到检测结果。
5. 先跑通、再优化：NMS 和逐 anchor 的 Python 循环在板端会很慢，
   建议用 NumPy 向量化；性能敏感时把后处理写成 C++。

## 五、注意事项（**重点，逐条对照**）

1. **输入是 NV12，不是 RGB。** 这是最容易踩的坑。板端不要多做一次 BGR↔RGB；PC 端验证时要么构造 NV12，要么直接用原 ONNX 走 RGB（因为 ONNX 输入是训练域 RGB）。
2. **坐标域 = letterbox 域。** 输出坐标是在 576×768 的 letterbox 画布里的；反映射必须减 pad、除 scale。**不要**直接用原图尺寸做比例缩放。
3. **预处理与反解必须成对。** 如果板端改用「直接 resize」而不是 letterbox，那么坐标反映射也要跟着改成直接缩放——两者错配会导致框全偏。
4. **`[4:16]` 是 12 类、`[16:20]` 是 4 颜色，别接反。** 本模型的段顺序已核实为 `box, cls(12), color(4), kpts(8)`。
   ⚠️ 但**不同导出（如 QAT 版）的顺序可能不同**（`axera.cpp` 里就是 `box, colors, objects, kpts`）。**以你手上这个 `.bin` 的实际输出为准**，不要照搬别的模型。
5. **阈值要先调。** 输出已是 Sigmoid 后的概率，直接用（不要再 sigmoid）。`conf_thres` 从 0.25 起调。
6. **NMS 用四边形 IoU，不要用普通框 IoU。** 装甲板是贴在目标上的四边形，用矩形 IoU 会误抑制。
   参考 `axera.cpp` 的 `pts_iou()`（用 4 点的 bounding rect 求交并），或用 poly IoU 库。
7. **关键点顺序可能要重排。** 参考实现用 `KPT_ORDER=[0,3,2,1]`；务必用可视化确认角点顺序对不对。
8. **box 是否已解码要验证。** 本模型的 anchor 解码（Slice/Sub/Add/Mul 链）在 **cut 之内**，
   所以 `[0:4]` 应是已解码的坐标；但 `axera.cpp` 的模型是把解码放到 CPU 的。
   **用下面的验证方法确认**，不要假设。
9. **9072 个候选**，注意向量化，别写纯 Python 三重循环；预先算好 stride 对应的 anchor 网格。
10. **模型是量化版（int8/int16）**，精度相比 float 有损失。若发现漏检/误检偏多，先确认是不是量化问题（见验收方法 3），
    再考虑把 `dart_576x768.yaml` 的 `calibration_type` 改成 `mix` 重新编译。
11. **AGPL-3.0 许可。** `AT_NN_Detector` 是 AGPL-3.0，衍生作品/网络服务需遵守其开源要求。

## 六、验证与验收（**关键：不要盲写**）

1. **离线正确性验证（强烈建议，最容易做对）：**
   在 PC 上用 `onnxruntime` 跑**完整模型** `praysky_coord_noe2e_0331_576x768.onnx`
   （它内置后处理，输出 `[1,30,18]` 即最终结果，30 = max_det）。
   同时跑你的 cut 后处理，在**同一张校验集图片**上比对两者的框/类别/关键点。
   两者接近 → 你的后处理对了；偏差大 → 回去查顺序/坐标/NMS。
   （完整模型在 PC 上能跑，只是不能编译到 X5，不影响这里当"标准答案"。）
2. **可视化**：把框、关键点、类别、颜色画到原图上，肉眼确认（参考 `preview.py` 的 `draw_detections`）。
3. **量化精度**：对比 `.bin`(板端) 与 float ONNX 的输出差异；差异过大再考虑 `mix` 量化。
4. **板端跑通**：确认输入 NV12 尺寸/对齐正确，输出能拿到 `[1,9072,28]`，后处理耗时满足帧率要求。
